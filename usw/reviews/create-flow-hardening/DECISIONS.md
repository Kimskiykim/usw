# Decision log: create-flow-hardening

Разбор находок по `usw-create-flow` (SKILL.md + спека guided-flow-authoring).
Append-only: записи только дописываются в конец.

- source-intent: «что можно улучшить в create_flow» → итеративный разбор
  6 кейсов совместно с пользователем.
- source-context: чат Claude Code, 2026-09-01.
- Итог разбора планируется оформить одним OpenSpec change.

## Кейс 1: `-s` на существующем flow

- Проблема: SKILL.md принимает селектор стиля всегда, но для существующего
  flow велит сохранять форму «без явной просьбы»; статус флага не определён —
  недетерминизм исполнителей.
- Решение пользователя (2026-09-01): **вариант 1** — переданный селектор
  стиля на существующем flow считается явной просьбой сменить стиль;
  перед записью обязательно показать черновик в новом стиле.
- Затрагивает: спека guided-flow-authoring (или markdown-flow-composition —
  уточнить при оформлении change), SKILL.md «Выбор точки входа».

## Кейс 2: подсказки design scan после применения одной

- Проблема: спека фиксирует лишь «повторный scan не запускать»; судьба
  остальных показанных подсказок не определена — буквалист откажет.
- Решение пользователя (2026-09-01): показанные подсказки остаются
  доступными и динамически актуализируются — перед применением следующей
  её фрагмент перепроверяется и при необходимости перерабатывается под
  уже изменённый текст flow. Новый scan не запускается.
- Затрагивает: guided-flow-authoring (Requirement про bounded design scan
  и revision), SKILL.md «Подсказки по проектированию».

## Кейс 7 (новый, из практики 2026-09-01): модель взаимодействия design scan

- Проблема: контракт подсказок «показать фрагмент + `применить`/`изменить`/
  `пропустить`» неудобен пользователю: варианты неговорящие, контекст правки
  не виден (нет диффа/места вставки), нет пространства для обсуждения и
  собственных вариантов.
- Решение пользователя: целевая модель — итеративное раскрытие проблематики
  (уточнения, споры, свои варианты) → явное решение: делаем сейчас или
  откладываем. Реализация принятого решения — отдельным вызовом
  (skill/flow/прямые правки), текущий flow при этом завершается. Свободные
  ответы пользователя допустимы; канонические статусы — только для лога.
  Подсказки показывать с контекстом (дифф до/после).
- Затрагивает: спека guided-flow-authoring (Requirement «Каждая подсказка
  применима» и revision-контракт), SKILL.md «Подсказки по проектированию»,
  «Проектирование от цели».
- Статус: принято, войдёт в общий change create-flow-hardening.

## Кейс 3: опасный дефолт origin

- Проблема: create без селектора пишет в общий `flows.root` и не смотрит
  другой origin; run-flow без селектора ищет локальный первым — тихий
  shadowing в обе стороны, дефолтный create и дефолтный run могут указывать
  на разные файлы.
- Решение пользователя (2026-09-01): **варианты 1 + 2 вместе** —
  1) кросс-origin проверка коллизии при создании: если имя нового flow
  существует в другом origin, остановиться и явно сообщить, что аналог уже
  есть (в shared или local соответственно), предупредить о shadowing при
  запуске без селектора; продолжать только после явного подтверждения или
  выбора другого имени;
  2) сменить дефолт origin для create на local — симметрично порядку поиска
  run-flow (local first), личные эксперименты не попадают в общий корень.
- Затрагивает: SKILL.md «Разбор запроса» (дефолт origin) и «Выбор точки
  входа» (кросс-origin проверка), спека guided-flow-authoring; смена дефолта —
  поведенческий breaking change, отметить в change.
- Статус: к-реализации, войдёт в общий change create-flow-hardening.

## Кейс 4: сигналы сложности слепы к обычному Markdown

- Проблема: из пяти сигналов сложности (SKILL.md «Сигналы сложности») три
  привязаны к маркерам `version-2`; для дефолтного обычного Markdown
  работают только «~12 шагов» и «вернуться к шагу N», хотя вложенные
  «если… то… иначе…» в прозе ломают исполнителя так же.
- Решение пользователя (2026-09-01): **вариант 2** — переформулировать
  сигналы формат-нейтрально: структура процесса первична (ветвление >4
  исходов, ветвление внутри ветвления, цикл с вложенным циклом/параллелью/
  вызовом flow, параллель >3 или с зависимыми ветками, неявные переходы),
  маркеры `version-2` — одно из представлений. Добавляется новый сигнал:
  вложенное ветвление без цикла. Дифф согласован в чате.
- Затрагивает: SKILL.md «Сигналы сложности» (полная замена списка), спека
  guided-flow-authoring синхронно; проверить стабильные токены тестов,
  привязанные к формулировкам сигналов.
- Статус: к-реализации, войдёт в общий change create-flow-hardening.
