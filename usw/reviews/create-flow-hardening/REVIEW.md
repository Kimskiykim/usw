# Ревью: usw-create-flow (SKILL.md + guided-flow-authoring)

Дата: 2026-09-01. Источник: разбор скилла, спеки, каталога рецептов и
eval-сценариев в чате Claude Code.

**1. Неоднозначность: `-s` на существующем flow.** Разбор запроса принимает
селектор стиля всегда, а «Выбор точки входа» (SKILL.md:59) велит сохранять
форму существующего flow «без явной просьбы сменить стиль». Считается ли
переданный `--structured` такой явной просьбой — нигде не сказано. Два разных
исполнителя решат по-разному.

**2. Судьба остальных подсказок после одного `применить`.** Спека фиксирует
«повторный scan не запускать», но не говорит, остаются ли две другие уже
показанные подсказки выбираемыми. Буквальное чтение может заставить
исполнителя отказать.

**3. Опасный дефолт origin.** Без селектора запись идёт в общий `flows.root`.
Создание локального flow с именем существующего общего (и наоборот) молча
создаёт shadowing, который стреляет в discovery.

**4. Сигналы сложности слепы к обычному Markdown.** Из пяти сигналов
(SKILL.md:82-89) к plain-flow применимы только «~12 шагов» и «вернуться к
шагу N» — вложенные «если… то… иначе…» в прозе ломают исполнителя не хуже
вложенных `LOOP`.

**5. Пробелы в eval-покрытии.** Шесть сценариев create покрывают happy paths;
нет сценариев на `ambiguous_flow_layout`, отказ по symlink/выходу за каталог,
сохранение contract tokens при конверсии в прозу, повторное применение
подсказки.

**6. «Безопасное kebab-case имя» не определено.** Ни длина, ни
зарезервированные имена, ни коллизия с packaged flows (change
`support-packaged-flows` в работе).

Мелочь: `agents/openai.yaml` в скилле — проверить актуальность.
