# Flow: refine-intent

Уточняет неоднозначное намерение по одному решению за ход. Это обычный
Markdown-flow: отдельный skill и runtime не требуются.

## Вход

- идея, проблема или запрос пользователя;
- необязательный kebab-case `refinement-id`;
- необязательный ответ на ранее заданный вопрос.

## Процесс

1. Найти корень проекта. Проверить, что `.usw` и `.usw/refinements` при
   наличии — реальные директории, а не symlink; при небезопасном или
   недоступном пути остановиться без записи. Определить по входу и контексту,
   это новое намерение или продолжение прежнего уточнения. Если это неясно,
   задать один вопрос и вернуть `decision_required`, не изменяя записи.
2. До использования итогового пути определить `refinement-id`:
   - Явный ID состоит из групп строчных латинских букв и цифр, разделённых
     одиночными дефисами. Имя `<refinement-id>.md` должно быть допустимо на
     текущей платформе и файловой системе, включая ограничения длины и, на
     Windows, зарезервированные имена устройств. Если ID или имя недопустимо,
     запросить корректный ID и вернуть `decision_required` без записи.
   - Для продолжения без явного ID использовать точный ID только если он
     однозначно известен из контекста прежнего уточнения; иначе запросить ID
     и вернуть `decision_required` без записи.
   - Для нового намерения без ID последовательно проверить `refine-1`,
     `refine-2`, …, `refine-1000` и выбрать первый, для которого путь
     `.usw/refinements/<refinement-id>.md` свободен. При отсутствии каталога
     кандидаты свободны; любой существующий объект, включая symlink, занят.
     Если свободного ID нет, запросить явный ID и вернуть `decision_required`.
3. Использовать локальный файл `.usw/refinements/<refinement-id>.md`. Для
   нового намерения проверить занятость пути без перехода по symlink. Если
   явный ID занят любым объектом, запросить другой ID и вернуть
   `decision_required`, не меняя объект. При необходимости создать каталог,
   затем создать файл эксклюзивно, без перезаписи. При коллизии во время
   создания для явного ID запросить другой ID; для автоматически выбранного —
   продолжить ограниченный поиск следующих кандидатов до `refine-1000`, затем
   запросить явный ID. В обоих случаях запроса вернуть `decision_required`.
   В новом файле сохранить исходное намерение и его контекст, цель,
   подтверждённые факты, допущения, открытые вопросы и журнал решений.
4. Для продолжения, не следуя symlink, прочитать существующий обычный файл и
   сопоставить его исходное намерение и контекст с текущим намерением или
   ответом на ранее заданный вопрос. Если файла нет, связь не подтверждается,
   данных недостаточно или намерения различаются, задать конкретный вопрос для
   выбора нужной записи или нового ID и вернуть `decision_required` без
   изменения файла. Совпадение ID само по себе не подтверждает связь.
   Продолжать только подтверждённую запись, сохраняя принятые решения. При
   небезопасном или недоступном пути остановиться без записи.
5. Если для подтверждённого продолжения получен ответ на ранее заданный
   вопрос, сначала записать подтверждённое решение и его последствия. Если
   решение пересмотрено, пометить старое как `superseded`, а не удалять.
   Каждый ответ обрабатывать только после повторной проверки шагов 1–4.
6. Если существенных открытых вопросов больше нет, записать согласованную
   формулировку намерения и вернуть `completed` со ссылкой на файл. Иначе
   выбрать ровно один существенно влияющий на результат вопрос, коротко
   объяснить его влияние, предложить два-три разных варианта, рекомендуемый
   показать первым, задать один вопрос и вернуть `decision_required`.

## Правила

- Один ход — один вопрос.
- Рекомендация не считается решением без подтверждения пользователя.
- Факты, допущения и неизвестное не смешиваются.
- Flow ничего не реализует и не выбирает следующий процесс; не изменять
  product files, спецификации или backlog.
