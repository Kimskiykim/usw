# Проверка результата

Предлагать, когда flow создаёт результат, но не подтверждает его корректность.
Сначала добавить наблюдаемую проверку: test command, validation или review.
`GATE` предлагать только в `version-2` и только когда разные результаты проверки
требуют разных следующих действий:

```markdown
1. Выполнить `<проверку>`.
2. GATE результата:
   - проверка успешна → продолжить;
   - проверка неуспешна → сообщить замечания и вернуть `decision_required`; исправлять только если это уже предусмотрено согласованным flow;
   - проверить невозможно → вернуть `blocked`.
```

Проверка отдельным участником реализует [Maker–checker](../patterns/maker-checker.md); цикл проверки и улучшения — отдельная композиция [Evaluator–optimizer](../patterns/evaluator-optimizer.md).
