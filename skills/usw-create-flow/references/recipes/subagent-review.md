# Ревью субагентами

Предлагать, когда качество результата оценивается суждением, а не
детерминированной проверкой, и цена ошибки заметна. Сначала предпочесть
наблюдаемую проверку (рецепт «Проверка результата»); ревью дополняет её, а не
заменяет.

Рекомендации по количеству и условиям:

- один reviewer по умолчанию; 2–3 независимых reviewer только для high-impact
  или необратимого результата;
- каждому reviewer — свой аспект: корректность, безопасность, полнота;
- reviewer работает read-only и возвращает вердикт с обоснованием;
- вердикты сводить одним `GATE`; расхождение reviewers — `decision_required`,
  а не автоматический повтор.

```markdown
PARALLEL:
- CALL `<review: корректность>`;
- CALL `<review: безопасность>`.

GATE сводного вердикта:
- все approve → продолжить;
- есть возражение → сообщить замечания и вернуть `decision_required`; доработка только если уже предусмотрена согласованным flow;
- reviewers расходятся → вернуть `decision_required`.
```

Не добавлять reviewers ради полноты: каждый лишний увеличивает стоимость и
шанс ложного расхождения.

Один независимый reviewer реализует [Maker–checker](../patterns/maker-checker.md) без обязательного цикла исправлений. Для нескольких независимых оценок одного предмета см. [Voting](independent-voting.md); разногласие не разрешается одним большинством.
