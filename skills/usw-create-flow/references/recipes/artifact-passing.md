# Передача артефактов

Предлагать для объёмных продуктов стадий: [Claim Check](../patterns/claim-check.md). Последовательный конвейер может сочетаться с оркестрацией, но не требует динамической декомпозиции.

- Каждому релевантному исполнителю дать прямой доступ к исходным требованиям; сводка не заменяет источник.
- Заранее объявить входы, выходы, формат и точные непересекающиеся пути под `artifacts.root` или `reviews.root`; один писатель на файл. Следующий участник получает путь, не выбирает его сам.
- Файлы — продукт: факты и результат, без курсоров стадий и статусов исполнения. При `handoff: false` не читать и не создавать handoff state; durable recovery state принадлежит только root operation.
- Существующий артефакт не переиспользовать молча: показать и вернуть `decision_required` для выбора человека.
- Краткий ответ содержит факт завершения, ссылку и версию. Привязку версии брать из применимого контракта (`execution-artifacts` для v1 задач), не вводить обязательную новую схему отчёта.
- Ревью получает исходные требования и фактический результат, а не только evidence автора. Факт завершения проверки отделён от вердикта; указать проверенную версию и непроверенные критерии. Изменение результата требует новой проверки, старое одобрение не переносится.

```markdown
1. CALL SUBAGENT `explorer`: прочитать требования; записать `<artifacts.root>/context-pack.md`.
2. CALL SUBAGENT `planner`: требования и context-pack; записать `<artifacts.root>/plan.md`.
3. CALL SUBAGENT `maker`: требования и plan; создать объявленный продукт; вернуть ссылку, версию и evidence.
4. CALL SUBAGENT `reviewer`: требования, фактический продукт этой версии и evidence; записать `<reviews.root>/review.md` с вердиктом и непроверенными критериями.
5. GATE: проверка завершена и все критерии подтверждены для актуальной версии → `completed`; иначе → `decision_required` с замечаниями и пробелами.
```

В обычном стиле: исследовать, спланировать, создать продукт и проверить его по исходным требованиям; передавать ссылки на объявленные файлы. Применимы контракты `text-flow-execution`, `nested-flow-execution`, `live-operation-state` и при необходимости `execution-artifacts`; отдельный протокол состояния не появляется.
