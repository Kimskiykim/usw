# Маршрутизация

Предлагать, когда разные типы входа требуют разных доступных действий. Паттерн: [Routing](../patterns/routing.md).
До выбора объявить признаки, доступные маршруты, вход и ожидаемый результат каждой ветки. Проверять реальную capability; название не разрешает её выдумать.

```markdown
1. CALL: определить тип запроса по объявленным признакам.
2. GATE:
   - документация → прочитать указанный документ и ответить со ссылкой;
   - тест → проверить указанный тест и вернуть наблюдаемый результат;
   - нет совпадения или несколько → `decision_required`, уточнить выбор;
   - нужная capability недоступна → `blocked`, объяснить ограничение.
```

В обычном стиле: определить тип и выполнить соответствующее действие; при неоднозначности спросить человека до действия. Эскалация и адаптивная интенсивность — специализированные варианты выбора, не обязательные дополнения.
