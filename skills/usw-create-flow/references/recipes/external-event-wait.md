# Ожидание внешнего события

Предлагать, когда следующий шаг зависит от внешнего процесса: CI, апрув в
другой системе, деплой. Не строить цикл опроса — scheduler в USW отсутствует,
и «повторять проверку, пока не пройдёт» либо бесконечен, либо жжёт бюджет:

```markdown
1. Выполнить `<проверку готовности>` один раз.
2. GATE готовности:
   - готово → продолжить;
   - не готово → вернуть `blocked`: назвать ожидаемое событие, как
     проверить его наступление и что resume этой operation продолжит
     с этого шага.
```

`blocked` с точным описанием ожидания — правильная форма; polling-цикл —
анти-паттерн, который assessment пометит как risk.
