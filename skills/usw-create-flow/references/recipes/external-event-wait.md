# Ожидание внешнего события

Предлагать, когда следующий шаг зависит от внешнего процесса: CI, апрув в
другой системе, деплой. Не строить цикл опроса: scheduler в USW отсутствует.

```markdown
1. Выполнить `<проверку готовности>` один раз.
2. GATE готовности:
   - готово → продолжить;
   - не готово → подготовить ответ: назвать ожидаемое событие, способ
     однократно проверить его и оставшееся действие;
     - при `handoff: false` включить контекст ручного повторного входа;
     - при `handoff: true` следовать действующему recovery contract и
       включить фактически сохранённый контекст;
     - вернуть `blocked` с подготовленным ответом.
```

При `handoff: false` добавить в ответ человеку контекст для ручного переноса
в новую сессию: имя flow, origin и проект, проверенные факты, ожидаемое событие,
способ одной проверки, оставшееся действие и ограничения повторов. Не обращаться
к handoff state и не обещать восстановления той же operation или перехода к
шагу. При явном новом запуске с этим контекстом снова проверить событие один
раз; не повторять автоматически уже выполненные эффекты.

При `handoff: true` следовать действующему recovery contract и сообщать только
фактически сохранённый контекст. Рецепт не включает handoff, не запускает flow
автоматически и не обещает scheduler или машинный курсор шага.

При адаптации к обычному Markdown выразить условие handoff и проверку простой
прозой; пример с GATE подходит для `version-2`. В обоих стилях включить оба
условия handoff в сам предлагаемый блок, сохранить `blocked` и одну проверку.
