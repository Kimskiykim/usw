# Эскалация

Предлагать, когда для одной проверки или решения есть дешёвый
детерминированный путь и дорогой глубокий. Начинать с дешёвого; дорогое
включать только когда дешёвое не справилось:

```markdown
1. Выполнить `<дешёвую проверку>`.
2. GATE результата:
   - успех → продолжить;
   - неуспех или неоднозначность → CALL `<глубокий анализ>`.
3. GATE анализа:
   - решено → продолжить;
   - не решено → вернуть `decision_required` с собранными фактами.
```

Правила: явный критерий эскалации на каждом уровне; не более трёх уровней;
последний уровень — человек или terminal outcome; на уровень не возвращаться
повторно.
