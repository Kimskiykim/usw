# Обработка ошибки

Предлагать только когда конкретный fallible шаг имеет значимый неуспешный
исход, требующий другого следующего действия, а flow описывает только happy
path:

```markdown
1. Выполнить действие.
2. GATE результата:
   - успешно → продолжить;
   - исправимая ошибка → вернуть на исправление;
   - внешний blocker → вернуть `blocked`;
   - неисправимая ошибка → вернуть `failed`.
```

Не придумывать automatic retry без доказанной безопасной повторяемости.
