# Последовательные стадии

Предлагать для заранее известных стадий с зависимыми результатами. Паттерн: [Pipeline](../patterns/pipeline.md). Субагенты и файлы не обязательны.
Объявить вход, выход и проверку каждой стадии. Не передавать неуспешный или неполный выход дальше как готовый.

```markdown
1. CALL: собрать факты по исходным требованиям; выход — проверенный набор фактов.
2. GATE: если вход неполон → `decision_required`, указать недостающее; иначе продолжить.
3. CALL: подготовить текст по фактам; выход — черновик.
4. CALL: сверить черновик с требованиями; сообщить результат проверки.
```

В обычном стиле: собрать и проверить факты; при нехватке уточнить; затем подготовить и проверить текст. Имя паттерна не становится полем flow.
