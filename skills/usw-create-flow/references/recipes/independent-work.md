# Независимые части работы

Предлагать для разных независимых частей одного результата: [Sectioning](../patterns/sectioning.md), форма [Fan-out / Fan-in](../patterns/fan-out-fan-in.md).
Объявить входы и выходы частей, владельца сборки и непересекающиеся записи. Зависимые шаги или общий изменяемый файл требуют последовательности. При отсутствии host параллельности выполнить части последовательно.

```markdown
PARALLEL:
- CALL: изучить модуль A; вернуть выводы и ссылки, без записи;
- CALL: изучить модуль B; вернуть выводы и ссылки, без записи.
1. Свести обе части по требованиям, указать пропуски и несовместимые выводы.
2. GATE: недостающая часть или неразрешённое расхождение → `decision_required`; проверены все части → `completed`.
```

В обычном стиле: независимо изучить два модуля, собрать выводы и явно отметить незавершённые части. Успех одной ветки не закрывает другую. Для проверок использовать более узкий рецепт [Независимые проверки](independent-checks.md).
