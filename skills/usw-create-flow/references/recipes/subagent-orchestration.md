# Оркестрация с субагентами

Предлагать, когда состав подзадач выясняется по входу или новым фактам, а результаты нужно свести в один итог. Паттерн: [Orchestrator–workers](../patterns/orchestrator-workers.md). Для заранее известных независимых частей достаточно [Sectioning](independent-work.md). Роль оркестратора исполняет сам flow; субагенты — его
ветки. Развёрнутый рабочий пример — packaged flow `chat-review`.

Контекст-пак каждой ветки — три явных блока:

- Scope: что именно делать и какие точные файлы или данные читать;
- Focus: аспект или критерий этой ветки;
- Output contract: ожидаемый результат, факты, ссылки и непроверенное для осмысленного сведения.

Правила:

- передавать ветке минимум необходимого; независимым параллельным веткам не передавать
  результаты друг друга — их независимость и есть ценность;
- зависимость между шагами выражать последовательными `CALL`, передавая
  результат предыдущего шага явно во входе следующего;
- результат ветки возвращается оркестратору в ответе: статус, факты, ссылки,
  blocker. Не заводить state-файл, папку или реестр на субагента —
  координация живёт у оркестратора, durable recovery state есть только у
  root operation;
- durable продукт выполнения (отчёт ревью, сгенерированный документ) пишет
  оркестратор после сводного `GATE`, по явно названному в flow пути; для
  ревью использовать configured `reviews.root`. Ветки держать read-only;
  если ветки обязаны писать — только непересекающиеся явно названные пути;
- потребность в durable state на каждую ветку — сигнал, что ветку пора
  выделить в отдельный flow.

```markdown
PARALLEL:
- CALL SUBAGENT `worker-a`: Scope, Focus, Output contract;
- CALL SUBAGENT `worker-b`: Scope, Focus, Output contract.

1. Свести результаты веток и провести один GATE общего итога.
2. Записать итоговый продукт в `<явный путь>`.
```

#### Выбор задач и границы

Координатор объявляет общий scope, предел назначений и критерий завершения, обнаруживает нужные подзадачи и после каждого возврата сверяет покрытие. Пропуск, конфликт или расширение scope вынести человеку с `decision_required`, отсутствие необходимой capability — `blocked`. Фиксированный конвейер по ролям сам по себе не является динамическим распределением.
Передача продуктов описана один раз в [Передаче артефактов](artifact-passing.md).

#### Ограниченные композиции

- [Иерархия](../patterns/hierarchical-decomposition.md): только при поддержке host; заранее задать максимальную глубину и число ветвей, каждому уровню Scope/Focus/Output contract и возврат родителю. Durable recovery state остаётся у root operation.
- [Обсуждение](../patterns/group-discussion.md): определить участников, общий предмет, порядок обмена позициями и предел раундов. Участники видят аргументы друг друга; независимость Voting здесь не заявлять. На пределе собрать согласованные факты и разногласия, использовать [Human decision](human-decision.md).
- [Изоляция контекста](../patterns/context-isolation.md): проверить режим host, дать прямые требования и релевантные входы, вернуть краткий результат. Это полезно и последовательно, с одинаковыми моделями. Полную историю по просьбе пользователя передавать допустимо, но не называть чистым контекстом.
