# Каталог рецептов design scan

Читать этот каталог при design scan и при проектировании от цели. Выбрать по
условиям ниже подходящие рецепты — при design scan не более трёх — и прочитать
только их файлы в `recipes/` и связанные выбранные карточки в `patterns/`. Не читать остальные.
Ссылки на внешние источники служат атрибуцией: обычное создание flow не требует сети.
Карточка объясняет идею и границы, рецепт даёт готовый блок, flow конкретизирует действия.
Каталог реализует контракты `flow-design-patterns` и `guided-flow-authoring`; OpenSpec в пользовательском проекте не требуется.

Примеры в рецептах показывают `version-2` форму. Не копировать их
structured-маркеры в обычный flow: для обычного flow выдавать готовый
нумерованный фрагмент простыми фразами — «попросить человека», «если результат
такой — сделать это», «повторить не более N раз» — без `CALL`, `GATE`, `LOOP`
и `PARALLEL`. Контрактные токены в обратных кавычках — статусы и варианты
решений вроде `approve`, `change`, `cancel` — при любой форме сохранять
дословно: это слова, которые человек вводит в ответ, и их перевод ломает
контракт.

## Рецепты

- [Проверка результата](recipes/result-check.md) — flow создаёт результат, но
  не подтверждает его корректность.
- [Human decision](recipes/human-decision.md) — несколько допустимых
  вариантов, и выбор меняет следующее действие или внешний эффект.
- [Подтверждение внешнего действия](recipes/external-action-approval.md) —
  flow содержит deploy, release, push, удаление или другой существенный side
  effect без явного подтверждения перед ним.
- [Обработка ошибки](recipes/error-handling.md) — fallible шаг со значимым
  неуспешным исходом, а описан только happy path.
- [Ограниченная доработка](recipes/bounded-refinement.md) — результат требует
  повторной проверки и исправления, повторяемые шаги безопасны.
- [Независимые проверки](recipes/independent-checks.md) — несколько read-only
  проверок, не зависящих друг от друга.
- [Ревью субагентами](recipes/subagent-review.md) — качество результата
  оценивается суждением, и цена ошибки заметна.
- [Оркестрация с субагентами](recipes/subagent-orchestration.md) — работа
  требует динамического выбора подзадач по обнаруженным фактам и сводного итога.
- [Эскалация](recipes/escalation.md) — есть дешёвая детерминированная
  проверка и дорогая глубокая.
- [Выбор из вариантов](recipes/variant-selection.md) — широкое пространство
  решений, цена неверного выбора выше стоимости альтернатив.
- [Сбор недостающих входов](recipes/input-preflight.md) — внешние входы или
  предусловия при наличии side effects.
- [Ожидание внешнего события](recipes/external-event-wait.md) — следующий шаг
  зависит от CI, апрува или другого внешнего процесса.
- [Адаптивная интенсивность](recipes/adaptive-intensity.md) — один flow
  обслуживает задачи разного риска.
- [Обработка списка элементов](recipes/list-processing.md) — одинаковая
  процедура для множества однотипных элементов.
- [Повторное использование capability](recipes/capability-reuse.md) —
  пользователь или flow явно называет установленный skill.

- [Последовательные стадии](recipes/sequential-stages.md) — известная цепочка зависимых результатов: [Pipeline / Sequential workflow / Prompt chaining](patterns/pipeline.md).
- [Маршрутизация](recipes/routing.md) — тип входа определяет доступную ветку: [Routing / Router / Dispatcher](patterns/routing.md).
- [Независимые части работы](recipes/independent-work.md) — разные части без зависимостей и пересечения записей: [Sectioning](patterns/sectioning.md).
- [Независимые оценки](recipes/independent-voting.md) — один предмет, независимые мнения и правило сведения: [Voting](patterns/voting.md).
- [Передача артефактов](recipes/artifact-passing.md) — объёмные результаты по доступным ссылкам: [Claim Check](patterns/claim-check.md).

## Связи и условия выбора

Это продолжение того же индекса; перечисленные подходы не добавляются ради полноты.

| Подход | Когда нужен; рецепт или зависимость |
| --- | --- |
| [Supervisor / Orchestrator–workers](patterns/orchestrator-workers.md) | Состав работ выясняется в ходе задачи; оркестрация с субагентами. Карточка также объясняет композицию через артефакты, Augmented LLM / retrieval / tools / memory и режим Agents. |
| [Evaluator–optimizer](patterns/evaluator-optimizer.md) | Проверяемое улучшение через ограниченную доработку и проверку результата. |
| [Maker–checker / Generate and review](patterns/maker-checker.md) | Отдельная проверка результата и ревью; цикл не обязателен, названия не точные синонимы. |
| [Fan-out / Fan-in](patterns/fan-out-fan-in.md) | Общая форма разделения и сведения; выбрать независимые части или оценки. |
| [Hierarchical decomposition](patterns/hierarchical-decomposition.md) | Крупные подобласти, host поддерживает вложенное делегирование; ограниченная композиция оркестрации. |
| [Group chat / Debate / Council](patterns/group-discussion.md) | Важен обмен аргументами; ограниченные раунды оркестрации и Human decision. |
| [Planner–executor–replanner / Magentic](patterns/planner-executor-replanner.md) | Новые факты меняют остаток плана; композиция ограниченной доработки. Magentic — связанный пример. |
| [Изоляция контекста](patterns/context-isolation.md) | Лишняя история мешает работе; режим host, входы и краткий ответ в оркестрации. |
| [Handoff](patterns/handoff.md) | Нужна передача активного управления: только при наличии механизма host; готового рецепта нет, recovery-handoff не подходит. |
| [Blackboard](patterns/blackboard.md) | Выбор работы по общим знаниям: нужны writers, согласованность и обработка конфликтов; готовой базы/планировщика нет. Альтернатива — назначения и Claim Check. |
| [Shared work queue](patterns/shared-work-queue.md) | Работники сами берут задачи: нужны атомарный захват и восстановление host; готовой очереди нет. Альтернатива — последовательное назначение. |

Независимые проверки — read-only вариант Sectioning; несколько ревью одного предмета могут использовать Voting. Эскалация и адаптивная интенсивность — специализированные варианты Routing. Для остальных рецептов не выдумывать обязательную связь с паттерном.
