# Создатель и проверяющий — Maker–checker

- **Проблема:** Самопроверка автора может пропустить собственную ошибку.
- **Применять:** Нужен отдельный взгляд на готовый результат.
- **Не применять:** Независимость не обеспечена либо цена проверки не оправдана.
- **Устройство:** Один создаёт, другой однократно проверяет; использовать проверку результата и ревью субагентом.
- **Ограничения:** Замечания сами по себе не разрешают исправления. Цикл улучшения — отдельный выбор Evaluator–optimizer.
- **Пример USW:** Автор готовит план, reviewer читает требования и план, сообщает замечания; дальнейшее решение принимает человек.
- **Проверка пользы:** Оценить найденные сверх самопроверки дефекты и стоимость ревью.
- **Происхождение:** Название взято из пользовательского исходника; [ADK](https://adk.dev/workflows/patterns/) описывает близкий Generate and review, не точный синоним. Здесь — адаптация USW.

Рецепты: [Проверка результата](../recipes/result-check.md), [Ревью субагентами](../recipes/subagent-review.md).
