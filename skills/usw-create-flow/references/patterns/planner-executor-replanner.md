# Планирование и пересмотр — Planner–executor–replanner

- **Проблема:** Новые факты могут сделать оставшийся план неверным.
- **Применять:** Выполнение даёт evidence для изменения ещё не выполненных шагов.
- **Не применять:** План стабилен или изменения означают неподтверждённое расширение scope.
- **Устройство:** Планировать, выполнить ограниченную часть, сравнить факты с планом и при необходимости пересмотреть остаток.
- **Ограничения:** Сохранять исходные требования и подтверждённые факты; ограничить перепланирования, не повторять внешние действия.
- **Пример USW:** После проверки зависимости заменить неприменимый оставшийся шаг, максимум два пересмотра; расширение цели согласовать.
- **Проверка пользы:** Сравнить число бесполезных шагов и стоимость перепланирования с фиксированным планом.
- **Происхождение:** [Microsoft](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/ai-agent-design-patterns): Magentic — связанный пример адаптивной оркестрации, не точный alias и не новая подсистема USW. Рецепт — композиция с ограниченной доработкой.
