# Подсказка о нотации version-2 при создании flow

## Проблема

`usw-create-flow` создаёт обычный Markdown по умолчанию и поддерживает
`--structured` (`-s`), но при создании нового flow без селектора не сообщает,
что существует нотация `version-2`. Пользователь узнаёт о ней только из README
или заранее знает команду.

## Поведение

Если обе точки входа нового flow отсутствуют и пользователь не передал
`--structured` или `-s`, `usw-create-flow` перед первым черновиком показывает
одну неблокирующую подсказку:

> По умолчанию я создам обычный Markdown flow. Для сложных процессов доступен
> режим `--structured` (`-s`) — нотация `version-2` с явными вызовами,
> развилками, циклами и параллельными шагами (`CALL`, `GATE`, `LOOP`,
> `PARALLEL`). Это подсказки для модели, а не исполняемый язык. Если не
> попросите иначе, продолжу в обычном формате.

Подсказка не требует ответа и не меняет выбранный стиль. Если пользователь до
записи явно просит переключиться, скилл читает `references/version-2.md` и
перестраивает черновик в `version-2`.

Подсказка не показывается при редактировании существующего flow и при явно
переданном селекторе стиля.

## Нормативные изменения

В спецификацию `markdown-flow-composition` добавляется требование, что новый flow
без селектора стиля до первого черновика получает краткое уведомление о
`version-2`. Обычный Markdown остаётся форматом по умолчанию; уведомление не
является выбором или `decision_required`.

## Проверка

Поведенческий сценарий создаёт новый flow без флага выбора стиля и проверяет,
что ответ до согласования черновика сообщает о `version-2`, `--structured` и
`-s`, при этом не записывает flow и не требует отдельного решения.

Дополнительные случаи:

- явный `--structured` не получает лишнюю подсказку;
- редактирование существующего обычного flow сохраняет стиль без подсказки;
- детерминированные тесты закрепляют только стабильные названия команд, а не
  точное предложение.

## Границы

Изменение не меняет формат flow, правила выбора точки входа, выполнение flow,
`version-2.md`, frontmatter или правила вызова. Новых файлов скилла и новых
зависимостей не требуется.
