# Явный корень проекта для USW

## Контекст

Сейчас часть USW-команд поднимается от переданного каталога до ближайшего
`.git`. Поэтому `/usw-init`, запущенный для открытой вложенной папки, создаёт
`usw.yaml`, `.usw/` и flow-каталоги в родительском Git-репозитории.

## Решение

USW использует корень открытого проекта, переданный агентом, буквально. Git не
участвует в выборе workspace: команды не ищут `.git`, не поднимаются по
родительским каталогам и не пытаются исправить неверно открытую пользователем
папку.

`project root` остаётся абсолютным реальным каталогом. Относительные пути из
`usw.yaml`, `.usw/` и встроенные defaults разрешаются только относительно него.

## Поверхность изменения

- `init_usw.py` перестаёт искать Git root и валидирует точный переданный путь.
- `handoff_state.py` применяет тот же контракт для всех операций handoff.
- `usw-run-flow`, `usw-find-flow`, `usw-assess-flow` и
  `usw-manage-handoff` требуют использовать корень открытого проекта без
  ancestor discovery.
- Python initialization и `llm-fallback.md` сохраняют одинаковую семантику.
- `run_flow.py` не меняется: он уже использует переданный `project_root`
  буквально.

## Поток данных

Команда делегирует установленному skill. Skill берёт корень текущего открытого
проекта из контекста агента и передаёт его скрипту. Скрипт нормализует путь,
проверяет, что это каталог, и выполняет все чтения и записи внутри него.

Если переданный путь отсутствует или не является каталогом, операция
останавливается с существующей наблюдаемой ошибкой. Поиск альтернативного
корня и fallback к Git root не выполняются.

## Проверка

TDD начинается с противоположных текущему поведению сценариев:

- initialization, получив вложенный каталог внутри родительского Git repo,
  создаёт inventory во вложенном каталоге и не меняет родителя;
- handoff, получив тот же каталог, читает и изменяет только его `.usw`;
- нормативные инструкции больше не содержат требования искать ближайший Git
  root.

После GREEN выполняются целевые тесты, полная сьюта на Python 3.10 и 3.13,
`openspec validate --all --strict` и `git diff --check`.

## Вне scope

- поиск ближайшего `usw.yaml`;
- поддержка нескольких вложенных USW workspace в одной команде;
- диагностика неверно открытой папки;
- изменение схемы `usw.yaml` или layout управляемых файлов.
