# Product Context

## Что за продукт

USW — самостоятельный workflow-слой для агентских CLI (Qwen Code, Codex,
Claude Code): пользователь описывает процессы как именованные Markdown flow,
модель исполняет их как текст. Плюс developer-local routed handoff для
передачи работы между сессиями.

## Пользователи

Разработчики, работающие через coding-агентов, и их команды (общие flow в
`flows.root`, личные — в `.usw/flows`).

## Ключевые сценарии

1. `/usw-init` — аддитивная инициализация workspace.
2. `$usw-create-flow` — создание/правка flow с design scan по рецептам.
3. `$usw-run-flow` — исполнение flow по одному текстовому пути.
4. `$usw-assess-flow` — семантическая оценка flow без запуска.
5. `/usw-find-flow` — поиск существующего flow по намерению.
6. `/usw-handoff`, `/usw-resume` — сохранение и восстановление операций.

## Что нельзя ломать

- Text-first исполнение: flow — текст для модели, не программа
  (см. `03-architecture.md`).
- Write-safety при любой записи в workspace.
- Flow не предоставляет полномочий на внешние действия.
- Совместимость двух entrypoint-раскладок; `ambiguous_flow_layout` при обеих.
- Аддитивность инициализации: существующие файлы не перезаписываются.

## Known limitations

- Исполнитель — модель: сложные flow исполняются ненадёжно, сигналы
  сложности предупреждают, но не блокируют.
- Assessment и evals — наблюдения модели, не machine guarantees.
- Независимость scope параллельных операций — заявление пользователя,
  USW конфликты в product files не обнаруживает.
