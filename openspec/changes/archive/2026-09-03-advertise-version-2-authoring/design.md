## Context

README и `usw-create-flow` уже описывают `version-2`, но инструкция читает
`references/version-2.md` только после явного `--structured` или `-s`. При
обычном создании нового flow пользователь не получает даже короткого сообщения
о доступном варианте.

## Goals / Non-Goals

**Goals:**

- показать одну понятную русскую подсказку до первого черновика нового flow;
- сохранить обычный Markdown форматом по умолчанию;
- позволить переключиться до записи без скрытой смены стиля;
- проверить поведение модельным сценарием, а не точной строкой в unit test.

**Non-Goals:**

- менять `version-2`, runtime, точку входа или правила безопасности записи;
- показывать подсказку при редактировании существующего flow;
- добавлять обязательный вопрос или новое состояние остановки.

## Decisions

Подсказка добавляется в основной путь проектирования `usw-create-flow`, а не в
README или metadata: только загруженная инструкция может надёжно повлиять на
ответ модели. Текст остаётся одним абзацем на русском; английскими остаются
только команды, имя нотации и маркеры.

Сообщение неблокирующее. Без явной просьбы переключиться скилл продолжает
обычный Markdown. При переключении до записи он читает существующий
`references/version-2.md` и заново показывает черновик.

Основная проверка — новый behavior-сценарий с отсутствующими точками входа и
ожиданием согласования структуры. Существующий сценарий flat-edit получает
запрет на лишнее упоминание `version-2`.

## Risks / Trade-offs

- Подсказка добавляет текст к каждому новому flow без выбора стиля → один
  короткий абзац показывается только один раз и не требует ответа.
- Проверка по маркерам не доказывает порядок сообщения и черновика → порядок
  подтверждается transcript при RED/GREEN измерении.
- Текущий основной checkout содержит незакоммиченный перевод `SKILL.md` →
  feature-коммиты создаются в чистом worktree, а одна новая вставка переносится
  поверх перевода отдельно.
