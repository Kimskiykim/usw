## Context

Контракт `.sync`-инструментов — байт-точное соответствие tracked-дерева
каноническому inventory по SHA-256. Текущая реализация полагается на
`git add`/`git clone` с настройками получателя, из-за чего результат зависит от
`core.autocrlf`, `core.safecrlf`, `core.filemode`, `.gitattributes` и
`.git/info/attributes`. Ревью зафиксировало ключевые контрпримеры:

- Замена LF-блоба каноническими CRLF при `autocrlf=true` нормализуется и
  ломает хеш; защита существующих CRLF-блобов действует только когда CRLF уже
  в индексе получателя по этому пути.
- `f.txt text` в `.git/info/attributes` реального target не попадает в
  обычный clone: клон проходит проверку unstaged-изменений, target — нет
  (`MM` против `M`).
- Смена `.gitattributes` снапшотом делает `unchanged`-файлы unstaged-грязными
  при чистом `verify_index`.
- `git restore` материализует файлы по действующим преобразованиям, а не
  восстанавливает прежние физические байты.

## Goals / Non-Goals

**Goals:**

- Все канонические текстовые blobs не содержат CR и используют только LF;
  binary с эффективным `-text` сохраняются без интерпретации.
- Индекс после apply байт-точно равен LF-каноническому inventory.
- Конфигурация, способная материализовать текст не как LF, обнаруживается до
  мутации реального target.
- Классификация отчёта различает доказанный индексный контракт, доказанную
  чистоту worktree и недоказанную готовность.
- Отчёты никогда не занижают факт мутации target, включая отказ отката.

**Non-Goals:**

- Автоматическое «исправление» конфигурации или атрибутов получателя;
  несовместимые зеркала отклоняются, постоянная политика атрибутов —
  отдельное согласование.
- Эмуляция Windows-ограничений имён/путей/симлинков (отдельная тема; здесь
  только честные stop-сообщения).
- Изменение идентификатора/версии или контейнера бандла, смысла
  `bundle_sha256` либо поддержка UTF-16 транспорта. Поле классификации `text`
  добавляется как совместимое metadata-расширение; новый reader принимает и
  ранее созданные бандлы без него.

## Decisions

1. **LF-инвариант на границе.** Для каждого пути читается эффективный `text`
   из канонического дерева (`git check-attr --source=<head>`). `-text` означает
   binary. Явный `text` означает text. Для `text=auto` и unspecified blob без
   NUL консервативно считается текстовым. Любой `\r` в таком blob отклоняется
   как `TEXT_EOL_NOT_LF`; binary не сканируется на EOL. Snapshot receiver
   повторно вычисляет классификацию по tracked `.gitattributes` внутри самого
   snapshot и не доверяет одному полю `text` manifest.
2. **Staging мимо фильтров.** `hash-object -w --no-filters --stdin` +
   `update-index --add --cacheinfo <mode>,<oid>,<path>`; удаления —
   `update-index --force-remove`. Байты symlink-блобов подаются через stdin и
   никогда не читаются по ссылке. Режим записывается буквально, что снимает
   зависимость от `core.filemode`.
3. **Воспроизведение среды в preflight.** Disposable-клон дополняется до
   checkout: копией `.git/info/attributes` target, значениями
   `core.autocrlf`, `core.eol`, `core.safecrlf`, `core.symlinks`,
   `core.ignorecase`, `core.filemode` из эффективного конфига target; затем
   `checkout`. Для `unchanged`-файлов сравниваются фактические worktree-байты
   target, а не байты клона: допустимые физические окончания в чистом target и
   свежем клоне могут различаться.
4. **LF-проверка итоговой среды.** После staging проверяются эффективные
   `text`/`eol` для итогового дерева, релевантный config и физические байты
   всех текстовых путей. `core.autocrlf=true`, `eol=crlf`, Windows-native EOL
   без явного LF либо несовпадение worktree-байтов с canonical дают
   `LF_WORKTREE_UNSUPPORTED`. Затем выполняется `git status
   --porcelain=v2` по всему tracked-дереву с предварительным сбросом
   stat-кеша (`update-index --really-refresh` в disposable-среде); unstaged
   `M` по любому tracked-пути — отказ. В preflight это даёт `UNSAFE_STOP /
   LF_WORKTREE_UNSUPPORTED` до мутации target; на реальном apply —
   транзакционный откат.
   В patch-маршруте CR-инвариант применяется к каноническим postimage из
   bundle; несвязанный byte-stable legacy CRLF в target не приписывается
   bundle. Явный source `-text`, отсутствующий в итоговых target attributes,
   даёт `ATTRIBUTE_SCOPE_MISMATCH` и требует включения `.gitattributes`.
5. **Разделение статусов.** `CONVERGED_STAGED` требует и индексного
   контракта, и чистоты worktree. Успех только cached-проверки при
   пропущенной или упавшей worktree-проверке — новый статус
   `INDEX_CONTRACT_ONLY` с ненулевым кодом выхода: готовность к обычному
   применению не доказана. Это правило классификации, а не диагностическое
   поле.
6. **Whitespace-диагностика.** Фиксированная стандартная политика Git без
   разрешения CR-at-EOL. Найденные дефекты — массив
   `whitespace_findings` в отчёте, не влияющий на outcome; невозможность
   выполнить проверку (ошибка Git, чтения индекса) — блокирующая.
7. **Rollback.** Исходный commit фиксируется до мутаций и используется и в
   `restore_backup`, и в выдаваемой команде. Отказ отката →
   `real_target_modified: true`, `rollback_completed: false`, список
   затронутых путей; ложная гарантия текущего обработчика устраняется.
8. **Транспорт.** Оба текстовых reader'а срезают UTF-8 BOM; байты, похожие на
   UTF-16 (BOM `FF FE`/`FE FF` или NUL в префиксе), дают явное сообщение
   «re-save as UTF-8/ASCII», а не generic-ошибку декодирования.
9. **Batch-инвентаризация.** Полные index-проверки читают уникальные object id
   одним `git cat-file --batch`; стоимость больше не включает subprocess на
   каждый tracked-путь.

## Risks / Trade-offs

- Консервативная классификация auto/unspecified может отклонить binary без NUL;
  такой путь нужно явно пометить `-text` в каноническом репозитории.
- Копирование конфига клона покрывает перечисленные ключи, а не произвольные
  clean/smudge-фильтры и `working-tree-encoding`; такие атрибуты при
  расхождении байтов ловятся постпроверкой (решение 3), но диагноз менее
  адресный. Принято: полный перенос фильтров тянет исполнение чужих команд в
  disposable-среде.
- `INDEX_CONTRACT_ONLY` меняет коды выхода для сценариев, ранее считавшихся
  успешными; это намеренное ужесточение честности отчёта.
- Регрессионные сценарии зависят от поведения установленного Git; тесты
  задают конфиг явно на каждый репозиторий и не полагаются на глобальные
  настройки машины.
- Patch-бандл встраивает text postimage для self-contained inspect, поэтому
  большие текстовые изменения занимают больше места, чем один patch.
