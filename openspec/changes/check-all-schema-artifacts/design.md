# Design

## Context

Мотивация — proposal.md. `opsx-intent2spec` является общим проектным Markdown
flow, а `intent-clarification` описывает другой example без planning.
CLI status возвращает `changeRoot`, `artifactPaths`, `artifacts` и `requires`;
instructions уточняет содержимое, условность и `existingOutputPaths`.
Готовность status определяется наличием файлов и не доказывает их полноту.

## Goals / Non-Goals

Цель — полнота проверки фактической схемы. Не добавлять parser схем, scheduler
или новый backend skill. Существующие human gates и два независимых ревью
сохраняются.

## Decisions

- Использовать status и instructions каждого artifact ID, сохраняя выбранный
  store, когда он задан. Жёсткая таблица по именам схем снова стала бы источником
  пропусков, поэтому контракт берётся из CLI при каждом шаге проверки.
- Проверять весь `artifacts`, включая компоненты вне замыкания applyRequires,
  все файлы glob и явно допустимые пропуски. Наличие tasks не подтверждает specs.
- Назначение задач и решений определять по инструкциям компонента. Не создавать
  tasks/design вне схемы. Если назначение неоднозначно и меняет действие,
  требовать уточнение, а не угадывать роль по имени файла.
- В обоих review scopes передавать конкретные пути всех файлов и инструкции;
  кросс-проверки охватывают зависимости и остальные содержательные связи.
- Сохранять перечень и результаты в существующем append-only decision log;
  отдельный runtime.json не нужен.

## Risks / Trade-offs

- Модель может пропустить компонент → адресные behavior scenarios и отчёт
  о покрытии. Stable-token тест проверяет только текстовый контракт.
- CLI или файл недоступен → blocked, без ложного clean.
- Схема не содержит задач → явно неприменимая проверка гранулярности задач;
  feasibility остальных компонентов остаётся обязательной.

## Migration Plan

Изменить общий flow через штатные prepare-write/write с токеном актуальной
версии. Установленные глобальные skills и пользовательские changes не менять.
Верификация: текстовый контракт, реальные ответы CLI на временных схемах,
behavior scenarios (при настроенном runner), полный unittest suite и OpenSpec.
