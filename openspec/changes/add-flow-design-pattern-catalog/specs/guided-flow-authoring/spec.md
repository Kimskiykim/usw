# Spec Delta

## MODIFIED Requirements

### Requirement: Подсказки используют bounded library рецептов
Design scan SHALL выбирать только из каталога `references/recipes.md`, который
охватывает проверку результата, human decision, подтверждение внешнего действия,
обработку ошибок, bounded refinement, независимые проверки, ревью субагентами,
оркестрацию с субагентами, эскалацию, выбор из вариантов, сбор недостающих
входов, обработку списка, ожидание внешнего события, адаптивную интенсивность и
явное повторное использование capability. Каталог SHALL также включать рецепты
последовательных стадий, маршрутизации, независимых частей работы, независимых
оценок и передачи артефактов, связанные с `flow-design-patterns`. Рецепт SHALL предлагаться только при
выполнении его условия из каталога и MUST NOT рекомендоваться просто для полноты.

#### Scenario: Результат не проверяется
- **WHEN** flow может завершиться без наблюдаемой проверки результата
- **THEN** skill предлагает шаг проверки и, только если разные outcomes требуют
  разных действий, decision gate после этой проверки

#### Scenario: У retry нет safety contract
- **WHEN** повтор может помочь, но неизвестны exit criterion, предел попыток или
  безопасность повторного действия
- **THEN** skill не предлагает неограниченный или автоматический retry

#### Scenario: Повторяемая работа имеет внешний side effect
- **WHEN** предлагаемое refinement повторило бы внешнюю запись или другое
  non-idempotent действие
- **THEN** skill оставляет это действие и его approval за пределами loop

#### Scenario: Проверки не независимы
- **WHEN** предлагаемые проверки зависят друг от друга или имеют пересекающиеся
  writes
- **THEN** skill не предлагает parallel execution

#### Scenario: Интенсивность контроля адаптируется к риску
- **WHEN** предложенный flow меняет интенсивность контроля по объявленным
  сигналам риска
- **THEN** сигналы являются наблюдаемыми фактами, обязательное подтверждение
  необратимого внешнего действия не отключается ни на одном уровне, а при
  неопределённых сигналах выбирается более высокий уровень


## ADDED Requirements

### Requirement: Выбор структуры объясняется через применимые паттерны
При проектировании от цели и design scan `usw-create-flow` SHALL называть связанные паттерны для выбранных рецептов, у которых каталог задаёт такую связь, и кратко объяснять пользу. Итоговые шаги SHALL быть понятными без знания названий. Skill MUST NOT выдумывать соответствие для остальных рецептов, добавлять паттерн ради полноты или превращать линейную задачу в команду агентов без необходимости.

#### Scenario: Пользователь просит простой линейный flow
- **WHEN** цель решается последовательными действиями без независимых веток или повторной оценки
- **THEN** черновик остаётся линейным; название Pipeline не добавляет исполнителей, артефактов или циклов

#### Scenario: Выбрана композиция подходов
- **WHEN** задача требует последовательных стадий, передачи объёмных результатов и доработки по критериям
- **THEN** skill объясняет Pipeline, Claim Check и Evaluator–optimizer, связывает их с рецептами и показывает один согласованный процесс

### Requirement: Чтение карточек сохраняет границы design scan
Skill SHALL сначала читать краткий каталог с условиями, связями и ограничениями паттернов, затем только карточки и файлы выбранных рецептов. Для явно названного подхода без готового рецепта SHALL читаться его карточка с зависимостями среды. При design scan лимит трёх подробных предложений SHALL считаться по рецептам, а не именам. Отклонённый рецепт MUST NOT возвращаться под alias; ограничения повторного scan сохраняются.

#### Scenario: Каталог содержит больше подходов чем требуется
- **WHEN** для цели выбраны два рецепта, каждый связан с карточкой паттерна
- **THEN** skill читает только соответствующие карточки и рецепты, не загружая весь справочник

#### Scenario: Отклонённая доработка названа иначе
- **WHEN** пользователь отклонил «Ограниченную доработку»
- **THEN** последующий scan не предлагает тот же блок как Evaluator–optimizer или через другой связанный рецепт

#### Scenario: Запрошен подход без готового механизма
- **WHEN** пользователь называет Blackboard, конкурентную очередь или Handoff, а необходимые возможности среды не подтверждены
- **THEN** skill читает соответствующую карточку, объясняет конкретное ограничение и предлагает применимую альтернативу без выдуманной capability и без записи до согласования

### Requirement: Полнота каталога не расширяет автоматически flow
Skill SHALL учитывать все позиции `flow-design-patterns` при явном запросе соответствующего подхода, включая композиции и зависимости среды. Наличие карточки MUST NOT само по себе создавать новый runtime, включать автономность, вызывать субагентов или добавлять блок в каждый flow. При композиции SHALL сохраняться критерии завершения и границы всех выбранных рецептов.

#### Scenario: Пользователь выбирает иерархическое делегирование
- **WHEN** задача требует нескольких уровней распределения и host поддерживает такое делегирование
- **THEN** skill показывает ограниченную композицию с глубиной и возвратом результатов, не создаёт отдельный persistent state каждого уровня

#### Scenario: Пользователь просит обсуждение специалистов
- **WHEN** важны ответы участников на аргументы друг друга
- **THEN** skill описывает ограниченные раунды обсуждения и его итог, а не подменяет запрос независимым Voting

### Requirement: Название паттерна не заменяет согласование и конкретизацию
Skill SHALL сохранять действующие правила preview, разрешения записи, origin, layout, стиля и contract tokens. Имена паттернов MUST NOT становиться обязательными метаданными flow или запускать его. Если названный пользователем паттерн противоречит зависимостям задачи, skill SHALL объяснить конкретную несовместимость и предложить подходящую структуру до записи.

#### Scenario: Запрошена параллельность зависимых записей
- **WHEN** пользователь предлагает Sectioning для двух стадий, изменяющих один файл по очереди
- **THEN** skill объясняет зависимость и предлагает последовательность; текст не утверждает безопасную параллельность только на основании названия

#### Scenario: Пользователь передал готовый текст flow
- **WHEN** пользователь просит сохранить согласованное тело без переработки
- **THEN** skill не переписывает его ради названий паттернов и сохраняет действующий контракт создания и design scan
