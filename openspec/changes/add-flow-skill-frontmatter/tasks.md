## Матрица новых eval

| Сценарий | Условие | Наблюдаемая проверка |
| --- | --- | --- |
| `create-flow-frontmatter` | Новое создание с готовыми шагами, обычный и structured варианты | `name` совпадает с целью, описание содержательно, тело согласовано, flow не исполнен |
| `create-optional-frontmatter` | Пользователь задал окружение, автора, версию и категорию; отдельный случай без дополнительных данных | Известные поля записаны с верными типами; неизвестные не выдуманы |
| `create-invalid-metadata-type` | `metadata.tags` — список либо `metadata.version` — число | Ошибка сообщена до записи, нет скрытой нормализации |
| `create-preserve-frontmatter` | Разрешена одна правка тела, есть многострочное описание, `compatibility`, `metadata` со строковыми значениями и неизвестные поля | Точный diff тела; заголовок и соседние ресурсы побайтно неизменны |
| `create-legacy-body-edit` | Старый flat flow без frontmatter | Правка шага без миграции, новой раскладки и скрытого заголовка |
| `create-frontmatter-preview` | Запрошен только заголовок в виде preview | Есть дифф; исходный файл побайтно неизменен |
| `create-exact-legacy-conflict` | Новый файл без заголовка требуют записать побайтно | Уточнение до записи; файл не создан |
| `find-by-description` | Имя не похоже на запрос, описание релевантно; есть отвлекающий flow | Найден правильный flow с исходным именем/origin; изменений файлов нет |
| `find-legacy-and-ambiguous` | Старый flow и два одинаково подходящих описания, отдельные случаи | Legacy доступен; при равенстве — `ambiguous` без исполнения |
| `assess-frontmatter-notice` | Некорректные метаданные и корректное тело; отдельно legacy | Замечание о метаданных не меняет вердикт само по себе; legacy не получает находку |
| `run-frontmatter-boundary` | Другое имя, указания разрешений, `metadata.version: "2"`, декларация сетевых требований и обычное тело | Нет переадресации/внешнего действия или смены стиля; требования не считаются выполненными без проверки, исходная identity сохранена |

Каждый независимый вариант таблицы оформляется отдельным входом/fixture.
Маркеры харнесса проверяют только заявленные ими свойства. Не приписывать им
проверку YAML, смысловой корректности описания или байт-точности `equals_flow`.

## Команды проверки

```sh
python3 -m unittest discover -s tests -v
openspec validate --all --strict
git diff --check
python3 evals/run_evals.py --list
```

Для модельных прогонов использовать `--runner`, `--runs 3`, `--scenario` и
`--transcripts` по `evals/README.md`. Runner должен передавать путь SKILL.md,
разрешать относительные ресурсы от его каталога и предоставлять штатные scripts;
для local authoring fixtures подготавливается `.usw`, для проверки shared без
инициализации — нет. Журналы: `.usw/state/add-flow-skill-frontmatter/`.
