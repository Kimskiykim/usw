# Design

## Context

См. proposal.md. Действующие спеки уже требуют сохранения существующих байтов
и удаления только partial file, созданного неудавшейся попыткой. Python
реализует эти правила; исправляется производный текст LLM path.

## Goals / Non-Goals

Согласовать инструкции с runtime и нормативным контрактом. Новая логика
хранения, автоматическое восстановление без доказательства владения файлом
и изменения пользовательских workspace исключены.

## Decisions

- До записи различать существовавшие, успешно созданные и недописанные файлы;
  очистка допускается только для последней категории текущей попытки.
  При неуверенности в принадлежности или безопасности пути остановиться.
- Для существующего HANDOFF использовать исходные байты, для созданного —
  пустой packaged router. Существующий operation directory допустим и не
  требует чтения или изменения operation documents в рамках init.
- Сослаться на workspace-configuration для допустимых roots и точно назвать
  исключение containment; metadata описывает только немедленный inventory.
- Fallback обещает только init. Python-зависимые create/run/find/assess/handoff
  не объявляются работоспособными без Python.

## Risks / Trade-offs

- Модель может неверно определить файл своей попытки → явное основание
  классификации и отказ от удаления при недостаточных данных.
- Подготовленное состояние после сбоя не равно настоящей I/O fault injection
  → записать точные ограничения наблюдения и отдельно результаты Python.
- Совпадение markers не доказывает сохранность → в адресном наблюдении
  сравнивать реальные байты файлов до и после.
